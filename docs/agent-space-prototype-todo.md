### 目标与执行约束

将真实协作过程呈现为动态二维工位：主席规划 → 创建任务 Agent → 弹簧入场 → 双方靠近和对话 → 返回工位执行 → 携带发现回传 → 主席审阅、追加任务或收队。

- 不再从旧的评估结果或节点日志猜测协作关系；允许新增存储结构和事件协议。
- 继续使用已接入的指定角色引擎，保留来源与声明；重点重做事件驱动、角色身份与场景编排，不再重复换头像。
- 主画面是二维工位；主席拥有明确的调度位置、身份和规划姿态。详情按需展开，不常驻占据半屏。
- 角色动作反映实际任务状态。微表情可以有独立节奏，但不得虚构派工、通信、思考内容或任务完成。
- 评分规则保持不变。准入链路目前没有主席，不能仅为展示伪造主席；是否改成真实主席调度单独确认后实施。
- 不删除旧数据、不改写旧历史以补造交接。新结构采用增量迁移；旧记录保留普通记录查看。
- 不操作浏览器，不自动部署、推送或合并分支。构建检查不等于视觉验收。
- 每完成一个任务立即勾选并记录证据；仅开始、代码初稿和未验证项不提前标为完成。用户验收不得代勾。
