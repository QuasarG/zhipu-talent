# 人才研究平台领域语言

本文件定义人才研究平台中容易混淆的核心业务术语。面试准入评估的功能规则与重建决策记录在 `docs/rebuild.md`。

## 人物与人才

**人物主档（Person）**：
系统对一个自然人的统一身份记录，可由人物调查或简历流程建立，不代表该人物已经进入人才库。
_Avoid_: 人才、候选人、嘉宾档案

**人才档案（Candidate）**：
已经由明确业务动作纳入人才库的人物记录，与人物主档一一关联。
_Avoid_: Person、搜索结果

**人才来源（Candidate Source）**：
人物成为人才档案的业务来源，可以是简历评估成功或人物调查后人工加入；同一人才可以同时拥有多个来源。
_Avoid_: 人才类型、固定分类

**HR 跟进状态（Engagement Status）**：
HR 对人才当前联系和推进阶段的人工记录，与能力评价、推荐 Track 和论文核验相互独立。
_Avoid_: 评估等级、筛选结论

## 业务流程

**候选人–JD 配对（Candidate–JD Pair）**：
一个候选人与一个具体 JD 构成的最小面试决策单元；同一候选人在不同 JD 下可以得到不同结论。
_Avoid_: 脱离 JD 的候选人总体准入结论、跨 JD 混合评估

**简历评估（Resume Evaluation）**：
对人才库中已有简历进行后续评价，并将人才与适合的 JD 建立匹配和关联；它不等同于面试准入决策。
_Avoid_: 面试初筛、面试准入评估

**面试准入评估（Interview Admission Assessment）**：
针对候选人–JD 配对，基于简历证据判断候选人是否达到岗位能力门槛的独立业务功能；它不评价候选人可用性，并与人才入库后的简历评估分开。
_Avoid_: 简历评估、通用人才评分

**面试准入评估批次（Interview Admission Batch）**：
由一批待筛简历和用人方在启动时从 JD 池明确选定的一个或多个 JD 组成的一次准入评估任务。
_Avoid_: 自动遍历整个 JD 池、由 JD 全局激活状态隐式决定范围、无目标岗位的通用评分

**评估输入锁（Assessment Input Lock）**：
面试准入评估运行期间对本轮使用的简历、JD、岗位补充要求和岗位评估卡施加的编辑禁令；无关候选人和无关 JD 不受影响。
_Avoid_: 运行中修改输入后丢弃结果、仅由前端按钮实现的软限制

**取消评估（Assessment Cancellation）**：
用户中途停止单个候选人–JD 配对或整个评估批次的操作；本轮未发出的工作停止，已在途结果不再生效，全部中间产物作废且不生成准入评估报告。
_Avoid_: 保存半成品报告、把取消记录当作有效评分、取消后继续占用输入锁

**评估运行失败（Assessment Run Failure）**：
模型超时、服务错误或其他技术故障导致候选人–JD 配对未能形成完整报告的运行状态；它不等于能力等级 0 或待确认，其他配对继续运行，并可从失败节点重试。
_Avoid_: 技术失败转成不进入面试、用缺失节点计算总分、整批任务连带失败

**LLM 运行轨迹（LLM Run Trace）**：
面向用户展示 LLM 工作步骤、状态与中间产物的轻量生长式视图；有持久结果的工作流使用自上而下并随当前结果保留的节点图，临时卡片关闭后轨迹随之关闭，对话节点链只在当前一轮调用运行时展示。
_Avoid_: 可拖拽知识图谱、只显示加载动画的黑箱、对话完成后长期保留节点链

**JD 池（JD Pool）**：
保存可供面试准入评估批次显式选择的 JD 集合；JD 本身不存在自动参与所有评估的激活或未激活状态。
_Avoid_: 全局激活 JD、默认参与评估的 JD 集合

**岗位评估卡（Role Assessment Card）**：
系统根据 JD 原文和已累计的补充要求生成的当前岗位判断基准，明确岗位核心任务与能力门槛；生成后无需人工确认即可用于评估，重新生成时替换原卡。
_Avoid_: 每份简历临时解释的 JD、等待审批的岗位草稿

**岗位评估卡质检（Role Card Review）**：
岗位评估卡生成后的自动质量检查，负责发现任务遗漏、重复或过度拆分，以及错误门槛和失真的任务化锚点；发现问题时最多退回修正一次，仍不合格则不替换当前卡。
_Avoid_: 人工审批、无上限反复生成、带缺陷的岗位卡直接生效

**岗位补充要求（Role Supplement）**：
用人方在 JD 原文之外维护的当前岗位上下文清单；补充要求可以增删改，并与 JD 原文共同参与岗位评估卡的原子重新生成，只有新卡生成成功后修改才生效。
_Avoid_: 不可修改的追加日志、候选人评价、旧补充要求历史链

**失效评估（Stale Assessment）**：
候选人的简历、对应岗位评估卡或评估规则发生变化时，该候选人–JD 的当前报告标记为失效并提示重新评估；系统只记录有效或失效，不向用户提供版本号。
_Avoid_: 无关候选人或 JD 的评分失效、自动沿用旧评分、面向用户的版本链

**强制重评（Forced Reassessment）**：
评估管理员在个人设置中启用后，对仍然有效的当前报告再次运行评估的诊断能力；当前仅用户 `guozexin` 拥有该开关，其他用户不可见。
_Avoid_: 普通用户重复抽取评分、面向所有用户的重新评估按钮

**候选人可用性（Candidate Availability）**：
候选人的到岗时间、可实习时长、工作地点和类似履约条件；它不属于面试准入评估的判断范围。
_Avoid_: 能力门槛、准入待确认项

**能力门槛（Capability Threshold）**：
候选人能够完成岗位核心任务所需的最低能力要求；学历和专业仅作为背景证据，不构成不可补偿的准入门禁。
_Avoid_: 学历门槛、专业门槛、候选人可用性

**简历证据块（Resume Evidence Block）**：
从完整脱敏简历中保留上下文的一段经历或成果，用于定位和引用而不替代简历本身；同一证据块可以用不同理由支撑多个核心任务，但不能伪装成多个独立来源，能力推理仍需读取完整脱敏简历。
_Avoid_: 拆散动作与结果的原子标签、作为后续节点唯一输入的证据列表、复制证据虚增来源数量

**评分证据（Scoring Evidence）**：
能够从完整脱敏简历中追溯、并直接支撑某项能力评分或准入结论的原文内容；每项评分必须绑定评分证据，评分节点可以从完整简历补充证据，但补充内容必须通过原文可追溯校验。
_Avoid_: 无引用的模型印象、仅凭关键词给分、无法回溯原文的概括

**证据纠错重评（Evidence Repair Reassessment）**：
评分证据无法追溯时，仅对受影响的核心任务进行一次纠错重评；再次失败则移除无效证据并按剩余证据降级，不影响其他任务评分。
_Avoid_: 整份候选人评估重跑、保留无法追溯的引用、无限重试

**核心任务评分项（Core-task Criterion）**：
岗位评估卡中一项边界清晰的核心工作任务，是候选人能力评分的主要维度；每张卡通常包含 3–5 项且最多 6 项，每项都把通用 0–4 能力尺度翻译成简短的任务化锚点，并依据候选人在实际项目中的问题、行动、责任和结果判断，不把特定工具或量化数字作为必需条件。
_Avoid_: 固定通用六维评分、关键词检查项、必须包含数字的成果模板

**核心任务能力等级（Core-task Capability Level）**：
候选人完成某项核心任务的 0–4 锚定等级，依次表示无证据、相关基础、实际参与、独立胜任和成熟胜任；百分制总分由这些等级确定性换算，任一首要任务低于 2 表示未达到岗位能力门槛。
_Avoid_: 模型自由生成的百分制分数、缺少等级锚点的小数评分

**核心任务重要性（Core-task Importance）**：
岗位评估卡生成时为核心任务固定的首要、主要或补充三档权重，换算系数依次为 3、2、1；使用同一张当前岗位评估卡的所有候选人共用，重新生成岗位评估卡时才变化。
_Avoid_: 针对候选人临时调整权重、模型自由生成百分比权重

**能力证据映射（Capability Evidence Mapping）**：
将完整脱敏简历中的直接证据、可迁移证据或背景证据关联到具体核心任务，并说明经历为何能够支撑该任务的判断过程；映射必须保留原文证据和适用边界，背景证据不能单独支撑能力等级 2 以上。
_Avoid_: 只返回证据编号的黑箱匹配、仅按技术关键词对应

**证据置信度（Evidence Confidence）**：
评分证据对能力判断的支撑充分程度，固定为高、中、低三档；它与候选人的核心任务能力等级相互独立，只作展示，不参与总分或面试准入公式。
_Avoid_: 百分比置信度、把能力高低重复表达为置信度、置信度隐藏扣分

**准入评估报告（Admission Assessment Report）**：
候选人–JD 配对的当前完整判断记录；无论是否进入面试，都展示各核心任务的证据、关联理由、迁移边界、能力等级、证据置信度和能力缺口，重评成功后由新报告直接替换。
_Avoid_: 仅展示通过者、只返回总分或未通过原因、可浏览的历史报告链

**面试重点（Interview Focus）**：
为进入面试的候选人生成、并绑定具体核心任务证据缺口或迁移边界的针对性验证问题；不进入面试者不生成。
_Avoid_: 通用面试题、脱离评分证据的追问、为不进入面试者生成问题

**JD 准入名单（JD Admission List）**：
一个面试准入评估批次按 JD 汇总的候选人结果列表，进入面试者优先并按总分排序，不进入面试者仍保留完整报告入口。
_Avoid_: 以候选人为主的跨 JD 混合总榜、隐藏不进入面试者、最佳 JD 推荐、排他岗位分配

**评分总审（Assessment Review）**：
汇总所有核心任务评分后检查等级锚点、跨任务矛盾、遗漏强证据和重复计分的总审；它可以纠错，但必须保留修改前后等级、修改原因和评分证据。
_Avoid_: 无审计记录地重写评分、重新自由评估整份简历

**面试准入结论（Interview Admission Decision）**：
候选人–JD 配对是否进入面试的二元结论，仅包括进入面试和不进入面试；进入面试要求所有首要任务能力等级不低于 2，且按任务重要性加权的百分制总分不低于 50。证据不足通过能力等级与证据置信度表达，不形成待确认状态。
_Avoid_: hold、待确认、脱离具体 JD 的候选人总体结论

**Track 推荐（Track Recommendation）**：
根据简历中体现的能力、项目、论文和技能，推荐一个或多个宽泛研究方向，并保留理由、证据与置信度。
_Avoid_: 录取方向

**入库身份归并（Intake Identity Resolution）**：
在建立或关联人才档案前，结合稳定标识和 AI 语义判断确定输入材料是否属于已有人物。
_Avoid_: 初筛、能力评分、人才分类

**已知人物调查（Known-person Investigation）**：
围绕一个可识别的具体人物，调查其研究范围、关键高引论文和公开舆情；它是人才知识 Agent 的一种意图，不再是独立产品入口。
_Avoid_: 独立人物调查产品、人才发现

**人才发现（Talent Discovery）**：
按研究关键词、机构或论文条件发现一批未知人物的流程，当前明确不在实现范围内。
_Avoid_: 已知人物调查

**人才库（Talent Pool）**：
保存已纳入人才的完整档案、来源和历史信息，支持查询、比较与人工管理，不是自动录取系统。
_Avoid_: 人物库、搜索结果库、自动筛选器

**人才库问答（Talent Pool Q&A）**：
通过自然语言检索、汇总和比较人才库已有信息的交互形式，回答必须能够追溯到具体人才档案和证据。
_Avoid_: 通用聊天、人才发现

**人才知识库（Talent Knowledge Base）**：
人才库的查询与呈现能力总称，同时包含对话问答和结构化浏览两种只读交互形式。
_Avoid_: 单一聊天界面、外部人才搜索引擎

**人才知识 Agent（Talent Knowledge Agent）**：
接收自由自然语言请求，识别人才查询或已知人物调查意图，并编排库内检索和外部工具形成带来源回答的 Agent 工作流。
_Avoid_: 固定人物调查表单、简历评估 Agent

**人才关系图（Talent Relationship Graph）**：
以人才、学校、机构和研究方向等实体及其有证据的关系构成的可视化知识图谱视图。
_Avoid_: 无来源社交关系、仅按姓名推断的关系

## 论文信息

**论文自述状态（Claimed Publication Status）**：
AI 根据简历原文语义提取的论文状态，属于候选人陈述，不等于外部事实已经确认。
_Avoid_: 核验状态

**论文核验状态（Publication Verification Status）**：
论文标题、发表信息和作者顺序与外部来源对齐后的状态，包括已核验、待核查和存在冲突。
_Avoid_: 投递状态、论文真假
