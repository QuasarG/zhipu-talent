# 面试准入评估 Workflow V2

## 使用场景

用人方已经有一批简历和一个或多个明确 JD，需要决定有限的面试资源应该给谁。
系统回答的是“这份简历是否值得针对这个 JD 进入面试”，不是候选人的抽象综合价值，
也不是最终录用结论。

## 核心语义

- 评估对象是 `候选人 × JD`，每个 JD 独立产出结论。
- 多 JD 不做加权平均；只在独立结论完成后推荐最匹配方向。
- 结论只有 `interview`、`hold`、`reject` 三种。
- `hold` 仅用于关键条件未知或接近面试阈值，不能容纳明显不匹配者。
- 简历没有写到的事实标记为 `unknown`，不得臆测为 `unmet`。
- 论文、学校、竞赛和稀缺经历只能成为岗位证据，不能冲掉硬门槛。
- 进入面试表示值得花面试资源进一步验证，不表示录用。

## 判定顺序

1. 逐条核对 JD 硬门槛，状态为 `met / unmet / unknown`。
2. 对六个固定维度评分并引用简历原文证据。
3. 确定性门禁根据硬门槛和维度分生成结论，模型不能绕过门禁。
4. 多 JD 结果按结论优先级、岗位匹配分排序，给出最匹配方向。

## 固定评价维度

| 维度 | 权重 | 判断重点 |
| --- | ---: | --- |
| 直接任务匹配 | 30 | 是否真正做过 JD 的核心工作，而非只出现相邻关键词 |
| 技术深度 | 20 | 方法细节、问题难度、关键技术判断和失败分析 |
| 本人贡献与主导性 | 15 | 候选人具体负责什么，是否拥有关键模块或决策 |
| 结果与证据质量 | 15 | 指标、上线、发表、开源、验收及证据可核验性 |
| 工程与规模 | 10 | 数据、训练、系统规模和端到端闭环 |
| 可迁移性 | 10 | 相邻经验迁移到 JD 核心任务的距离与可信度 |

硬门槛单独判断，不进入加权分，避免高潜力或学术履历补偿明确不满足的条件。

## 确定性门禁

- 任一硬门槛为 `unmet`：`reject`。
- 没有 `unmet`，但任一硬门槛为 `unknown`：只有岗位匹配分不低于 55 且直接任务匹配不低于 2.5/5 时才 `hold`，否则 `reject`。
- 硬门槛均满足时，岗位匹配分不低于 70 且直接任务匹配不低于 3/5：`interview`。
- 硬门槛均满足时，岗位匹配分不低于 55 且直接任务匹配不低于 2.5/5：`hold`。
- 其他情况：`reject`。

阈值是可版本化的招聘策略，不由提示词临时发挥。

## 深模块 interface

```python
evaluate_candidate_against_jobs(resume, jobs, llm=None) -> CandidateJobFitEvaluation
```

调用者只负责提供一份结构化简历和待评估 JD。模块内部用一次模型调用完成全部 JD
的独立证据对照，再执行确定性门禁、补齐缺失维度和最匹配方向排序。调用者不需要知道
提示词、分数归一、门禁优先级或异常输出修复。

## Workflow

```text
candidate_preparer -> jd_fit_assessor -> decision_guard -> result_formatter
```

其中只有 `jd_fit_assessor` 调用模型。旧的 Track 路由、通用分、跨 Track 聚合、论文加分和
特殊优势兜底不再参与面试准入结论。即使批量评估从多个后台线程启动，模型请求默认也会
通过进程内门禁串行执行；可用 `JOB_FIT_MAX_CONCURRENCY` 显式调整并发上限。
