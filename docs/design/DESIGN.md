# 界面设计准则

> 状态：Active
> 更新时间：2026-08-25
> 产品规则：[../rebuild.md](../rebuild.md)
> 领域语言：[../CONTEXT.md](../CONTEXT.md)

## 1. 设计命题

这是给用人方决策者、技术面试官和 HR 长时间使用的人才研究工作台。页面的单一职责是让用户快速理解：系统正在做什么、依据什么得出结论、下一步该看哪里。

界面不是招聘营销页，也不是炫技的 AI 画布。它应像一台安静、精确、证据可回溯的研究仪器。

本产品唯一需要被记住的视觉特征是：

> LLM 的真实工作步骤以节点和连线从上到下生长，结果在用户眼前逐步形成。

其他视觉元素必须克制，不能与运行轨迹争夺注意力。

## 2. 视觉语言

### 2.1 色彩

使用接近纸面和研究工具的中性色，语义色只表达状态：

| Token | 色值 | 用途 |
| --- | --- | --- |
| `canvas` | `#F7F8FA` | 页面背景 |
| `surface` | `#FFFFFF` | 主工作面板 |
| `ink` | `#17191C` | 主文字和关键操作 |
| `muted` | `#66707A` | 辅助说明 |
| `line` | `#DDE2E7` | 分隔、节点连线、边框 |
| `success` | `#2E8B57` | 完成、进入面试、有效证据 |
| `warning` | `#B7791F` | 低置信、失效、降级 |
| `danger` | `#D24B4B` | 失败、不进入面试、证据冲突 |

黑色用于主操作和当前焦点。避免大面积蓝紫渐变、发光球、玻璃拟态叠层和无业务含义的彩色卡片墙。

### 2.2 字体与数字

- 中文正文：`PingFang SC`、`Microsoft YaHei`、系统无衬线回退。
- 英文和数字：`Inter` 或系统无衬线。
- ID、模型名、耗时和分数使用等宽或 tabular numerals。
- 正文 14px，辅助 12–13px，区块标题 16–20px；不使用营销式超大标题。
- 能力等级和总分必须同时有文字含义，不能只放一个巨大数字。

### 2.3 形状与层级

- 数据面板圆角 8px，节点圆角 8px。
- 胶囊只用于状态、筛选和模式切换。
- 阴影只用于菜单、对话框等真正脱离文档流的临时层。
- 工作流节点、导入运行卡和评估结果均位于正常布局中，不使用漂浮玻璃卡。
- 避免卡片套卡片；使用分隔线、缩进和留白表达结构。

### 2.4 动效

- 节点出现：160–220ms 的淡入与轻微向下展开。
- 连线生长：从父节点向子节点推进，严格对应真实事件。
- 并行节点可以同时进入运行态，但布局保持纵向。
- 完成态只点亮一次，不持续发光或呼吸。
- 支持 `prefers-reduced-motion`，降级为无位移的即时状态切换。
- 禁止用定时器伪造步骤、预计耗时或进度。

## 3. 信息架构

主导航保留：

- 面试准入评估；
- 人才问答；
- JD 池；
- 人才库；
- 奖学金；
- 设置。

“简历评估”和“面试准入评估”是不同领域功能。当前重建期间，界面文案必须优先使用“面试准入评估”，避免继续把旧 Track 评估语义混入。

## 4. 面试准入评估工作台

### 4.1 桌面布局

完整桌面保留三栏结构：

```text
┌─────────────┬────────────────────┬────────────────────────┐
│ 候选人队列   │ 结构化简历 / 原件   │ 评估结果 / 运行过程       │
│ 约 280px     │ 弹性宽度            │ 弹性宽度                 │
└─────────────┴────────────────────┴────────────────────────┘
```

右栏的“评估结果”和“运行过程”是同级视图。切换不改变三栏宽度，不打开新的浮层。

### 4.2 启动评估

- 启动时显式选择一批简历和一个或多个 JD。
- 提交前显示 `N 份简历 × M 个 JD = N×M 个配对`。
- 页面不再出现“激活 JD 后自动参与评估”的隐式联动。
- 输入被运行任务锁定时，编辑控件显示原因和受影响任务。

### 4.3 结果视图

主结果按 JD 组织：

- 每个 JD 一个页签或分区；
- 进入面试者在前，按总分排序；
- 不进入面试者在后，仍展示总分和首要能力缺口；
- 点击候选人查看完整的核心任务报告；
- 不显示最佳 JD、跨 JD 总榜或排他分配。

候选人–JD 报告的阅读顺序：

1. 二元准入结论和总分公式；
2. 首要任务是否跨过等级 2；
3. 各核心任务的等级、置信度和能力缺口；
4. 证据、关联理由和迁移边界；
5. 评分总审的修改记录；
6. 进入面试者的针对性面试重点。

进入和不进入面试使用语义色辅助区分，但不能依赖颜色；必须同时显示明确文字与图标。

## 5. 生长式 LLM 运行轨迹

### 5.1 通用节点

每个节点默认包含：

- 业务名称；
- 排队、运行、完成、失败、取消或跳过状态；
- 一句结果摘要；
- 实际模型与降级标记；
- 开始、结束时间和耗时。

点击或键盘展开后显示结构化中间产物。普通用户不查看完整 prompt、原始 chain-of-thought 或内部异常堆栈。

### 5.2 布局

- 固定自上而下布局，不允许拖拽、缩放或自由连线。
- 只渲染真实存在的依赖边。
- 尚未创建的节点不占据视觉位置；节点随后端事件生长出来。
- 并行核心任务位于一个纵向任务组中，可以同时运行，不做宽度失控的横向树。
- 失败节点就地展示错误与局部重试，不把用户抛到通用错误页。

### 5.3 面试准入轨迹

显示顺序：

```text
准备输入
  ↓
能力证据映射
  ↓
核心任务评分组
  ↓
证据校验与局部修正
  ↓
评分总审
  ↓
准入决策与报告
```

核心任务节点展开后固定展示：

```text
证据 → 关联理由 → 迁移边界 → 能力等级 → 证据置信度
```

评分总审节点展示所有“原等级 → 新等级”的纠错及依据，不能只显示“复核完成”。

### 5.4 对话 Agent

人才问答和画像澄清仍以消息为主。当前一轮运行期间，在消息中内嵌轻量节点链展示理解、工具调用、结果读取和回答生成；本轮回答完成后节点链消失，不作为长期聊天内容保留。

## 6. 简历导入运行卡

导入运行卡不是弹窗或浮动遮罩。它插入左侧候选人队列底部、固定在底部操作栏上方：

```text
┌─────────────────────┐
│ 搜索 / 队列筛选       │
├─────────────────────┤
│ 候选人列表（独立滚动） │
├─────────────────────┤
│ 导入运行卡             │
│ 读取文件               │
│   ↓                   │
│ 识别内容               │
│   ↓                   │
│ 结构化解析             │
│   ↓                   │
│ 保存候选人             │
├─────────────────────┤
│ 导入简历 / 批量操作     │
└─────────────────────┘
```

规则：

- 候选人列表让出高度并滚动，运行卡始终可见。
- 运行期间没有关闭按钮，点击其他区域不能使其消失。
- 批量导入显示总体进度，并能查看当前文件。
- 全部成功后显示完成态约 2 秒并自动退场。
- 部分或全部失败时保留失败文件、重试和确认关闭入口。
- 导入轨迹不进入人才档案，不形成历史记录。

## 7. JD 池

- 删除“激活 / 停用”操作和状态文案。
- JD 卡展示标题、团队、原文、当前补充要求和岗位评估卡摘要。
- 补充要求以可增删改的当前清单呈现。
- 主操作统一命名为“保存要求并重新生成岗位评估卡”。
- 生成过程使用纵向运行轨迹；成功才整体替换，失败保留原卡。
- 当前卡变化后，受影响的评估报告显示“已失效，需要重评”。

## 8. 权限与设置

- 普通用户看不到有效报告的“重新评估”操作。
- 只有用户 `guozexin` 在设置中看到“允许强制重评”开关。
- 开关关闭时，管理员界面与普通用户一致。
- 强制重评不提供历史版本对比；成功直接替换，失败保留当前报告。
- 任何禁用操作必须说明原因，不能只显示灰色按钮。

## 9. 状态与文案

运行状态和业务结论必须分开：

- 运行状态：排队、运行中、已完成、失败、已取消。
- 业务结论：进入面试、不进入面试。
- 报告状态：有效、失效。
- 模型状态：主模型、已降级。

禁止使用：

- `hold`、待确认准入；
- S/A/B/C 人才档位；
- “综合判断”“系统认为”等无证据文案；
- 把模型调用失败显示成候选人不合格。

失败文案说明发生了什么以及如何恢复，例如“核心任务评分请求失败，可从该节点重试”，而不是“系统异常，请稍后再试”。

## 10. 可访问性与响应式

- 目标 WCAG 2.1 AA。
- 状态同时使用文字、图标和颜色。
- 节点和证据展开支持键盘，焦点清晰。
- 运行事件使用克制的 `aria-live`，避免每个 token 打断屏幕阅读器。
- 小于 1280px 时，候选人队列可折叠为抽屉，结果与简历使用页签；不能把三栏硬挤到一起。
- 小于 768px 以查看结果为主，批次配置和复杂证据对比允许提示使用桌面端。
- 所有关键内容不依赖 hover；触摸目标不小于 44px。

## 11. 实现约束

- 复用现有 React、Tailwind 和 `frontend/src/components/ui/`，不引入第二套组件库。
- 新建统一的 `LLMRunTrace` 视觉组件和事件适配层，各业务提供节点数据，不复制样式与状态机。
- 前端只能渲染后端真实事件，不自行推演工作流状态。
- PDF、长证据和运行详情按需渲染；候选人列表和大批次结果需要虚拟化。
- 所有重要页面在 1440px、1280px 和 390px 宽度下检查溢出、焦点和 reduced motion。

后续实现若需要新增视觉模式，必须先证明它不能由现有运行轨迹、数据面板或对话节点链表达；不能为了单个页面再造一套“AI 感”组件。
