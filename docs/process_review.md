# 过程复盘

## 评估维度

本工具把“高潜 AI 人才”拆成 7 个维度：学习与成长潜力、研究探索能力、工程实践能力、AI 工具 / Agent 使用能力、问题定义与独立思考能力、项目 ownership、长期培养价值。

选择这些维度，是因为任务目标不是传统招聘里的“谁学校更亮、论文更多”，而是判断候选人是否可能成长为 AGI 时代的研究者、工程师或技术 leader。学校、GPA、会议名只能作为背景信息；真正有用的是候选人是否能定义问题、搭建可运行闭环、验证假设、复盘失败，并把 AI 工具变成自己的能力杠杆。

打分方式采用统一 Rubric。不同方向不直接比较“谁的 mAP 更高”或“谁的论文更像顶会”，而是把 Evidence List 放进同一套维度中评分。每条证据会标记具体工具、动作动词、量化结果和 ownership 信号。证据越具体，评分越高；只有“参与项目”“了解方向”这类表述会被压低。

## 关键 Prompt / Agent 指令片段

证据挖掘 Prompt：

```text
不要告诉我候选人做过什么项目。
请像尽调律师一样，从简历中抽取候选人为完成项目实际做过的动作：
具体调用了什么工具或库？解决了什么技术难点？有没有量化结果？
每条判断必须绑定原文引文，不允许补写简历没有出现的信息。
```

跨领域打分 Prompt：

```text
不要比较 CV、NLP、Agent、AI4Science 的单项指标。
只基于 Evidence List，按工程闭环、AI 杠杆、问题定义、研究探索、ownership 等统一维度打分。
如果某维度缺少可验证证据，即使候选人背景很好也要保守给分。
```

Critic Prompt：

```text
逐条检查评分理由中的引文是否出现在原简历。
如果引文不存在，标记为疑似幻觉。
如果某维度接近满分，但证据中没有具体工具、量化结果或本人负责动作，要求回炉重打分。
```

## 踩坑与处理

第一个坑是过度依赖背景信号。Normalizer 会把学校、排名、GPA 盲化成粗粒度占位，Scorer 不直接读取原始教育背景。

第二个坑是证据和判断混在一起。现在模型层把 `EvidenceItem` 和 `DimensionScore` 分开，Formatter 只能基于 Evidence 生成优势、风险和追问。

第三个坑是 Critic 误报。最初技能关键词在证据中被合并成一行，但 Normalizer 原文里是逐项保存，导致 Critic 误判为“疑似幻觉”。修复方式是让 Normalizer 保存与证据抽取一致的技能 / 方向合并文本，并增加回归测试。

## 当前局限

当前只支持 JSONL / Markdown 文本简历，暂未处理 PDF 版式。论文、GitHub 链接、实验结果和开源贡献也没有联网核验，所以只能生成“待验证点”，不能替代人工背调。

评分仍然是启发式规则，没有接入真实大模型做语义级反思。好处是 Demo 稳定、可离线运行；代价是对隐含能力和复杂语义的理解有限。

## 再给两天会做什么

第一，接入 OpenAI-compatible JSON 模式，把 Evidence Extractor 和 Critic 升级为 LLM + 规则双通道。第二，支持 PDF 解析，并把版式质量作为弱信号。第三，为论文、GitHub、项目链接增加外部核验入口。第四，引入人工复核界面，让 HR 能修改证据权重并保存反馈，形成下一轮校准数据。
